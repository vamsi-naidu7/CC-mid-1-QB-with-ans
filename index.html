Cloud Computing Question Bank Answers

Unit 1

Q1. Define Cloud Computing. (2M)

Cloud Computing is a technology that allows you to store and access data and applications over the internet instead of using your computer’s hard drive or a local server. It is a paradigm shift from local to network-centric computing and network-centric content, where distant data centers provide computing and storage resources.

Q2. List the types of computing. (2M)
  • Distributed Computing
  • Parallel Computing
  • Cluster Computing
  • Grid Computing
  • Utility Computing
  • Edge Computing
  • Fog Computing
Q3. State any two needs for cloud computing. (2M)
  • Scalability and Elasticity: Clouds offer the ability to dynamically acquire and release computing resources to support variable workloads.
  • Cost-Effectiveness: Due to the multiplexing of resources and economy of scale, it eliminates the need for users to invest in their own computing infrastructure, significantly reducing maintenance and operation costs.
Q4. What are the main components of Cloud Computing Architecture? (2M)

The main components are broadly classified into the Front End and the Back End. Specific components include:

  • Client infrastructure
  • Application
  • Service
  • Runtime cloud
  • Storage
  • Infrastructure
  • Management
  • Security
  • Internet
Q5. Differentiate between network-centric computing and network-centric content. (2M)

Network Centric Computing (NCC): An architectural approach where computing resources, data, and applications are distributed and interconnected over a network (like the internet) rather than being local.

Network Centric Content: Refers to the storage and accessibility of media and information over the network rather than being confined to local devices, allowing access from any internet-connected device (e.g., iCloud).

Q6. Name the three primary cloud service models. (2M)
  • Infrastructure as a Service (IaaS)
  • Platform as a Service (PaaS)

Q7. Define cloud computing and explain its essential characteristics. (6M)

Definition: Cloud Computing is a technology that allows storing and accessing data and applications over the internet instead of a local hard drive. It shifts from local to network-centric computing, utilizing distant data centers for resources.

Essential Characteristics:

  • Elastic Services: Dynamically acquires and releases computing resources to support variable workloads using internet technologies.
  • Metered Usage: Resources are metered, allowing users to be charged only for what they consume (pay-as-you-go).
  • Provider-Managed Maintenance and Security: The service providers take responsibility for ensuring system maintenance and robust security.
  • Economy of Scale: Specialization and centralization lead to lower costs through resource multiplexing, which are passed on to users.
  • Device and Location Independent Data Storage: Application data is stored closer to where it is used, independent of the device or location, improving reliability and lowering communication costs.
Q8. Explain the layered architecture of cloud computing. (6M)

The layered architecture of cloud computing defines how different components interact to deliver services. It consists primarily of two major parts: Front End and Back End, separated by the Internet.

  • Front End: The client-side interface that the end user interacts with. It includes client infrastructure like browsers, tablets, and mobile devices used to connect to the cloud.
  • Back End: The cloud side managed by the service provider. It processes data and manages resources. Components include:
    • Application: The software/app clients access.
    • Service: Manages the type of service (IaaS, PaaS, SaaS).
    • Runtime Cloud: Offers virtual machine implementation and execution environments.
    • Storage: Space in the cloud for managing data.
    • Infrastructure: Hardware and software backing the cloud (servers, network devices).
    • Management & Security: Controls backend components, establishes coordination, and ensures data safety.

In the context of Network Centric Computing, the layers include:

  • Information Service Layer: Manages data/objects, focusing on security and integrity.
  • Network Service Layer: Handles communication, configuration, and performance management.
  • Component Control Layer: Responsible for the infrastructure components for distributed computing.
Q9. Explain various computing service models (IaaS, PaaS, SaaS). (6M)

1. Infrastructure as a Service (IaaS): Gives users access to IT tools like virtual computers, storage, and networks over the internet. Users pay for what they use without managing physical hardware.

  • Control: High control over OS and apps, but not physical infrastructure.
  • Example: Amazon Web Services (EC2).

2. Platform as a Service (PaaS): A third-party provider offers software and hardware tools needed to develop, test, and run applications.

  • Control: Simplifies development by abstracting infrastructure. Users control deployed apps but not the underlying OS/network.
  • Example: Google AppEngine, AWS Elastic Beanstalk.

3. Software as a Service (SaaS): Using software hosted over the internet through a browser, eliminating local installation.

  • Control: Provider handles maintenance, updates, and infrastructure. User only controls limited app settings.
  • Example: Google Docs, Gmail.

Q10. Explain distributed systems architecture in detail. (6M)

Cloud computing is built upon principles of distributed systems, which consist of independent computer nodes working together as a coherent system. Key architectural styles include:

  • Client-Server: Servers provide resources/services, and clients request them. Clear separation of responsibilities (e.g., Web browser and Web server).
  • Peer-to-Peer (P2P): Each node acts as both client and server, sharing resources directly without a central server (e.g., BitTorrent).
  • Multi-tier (N-tier): Application is separated into logical layers (Presentation, Logic, Data tiers) to improve scalability and maintainability.
  • Microservices: Application structured as small, independent services communicating via APIs. Enables loose coupling and independent deployment (e.g., Netflix).
  • Service-Oriented Architecture (SOA): Organizes functions as reusable services communicating via an Enterprise Service Bus (ESB) for interoperability.
  • Event-Driven Architecture (EDA): Components interact by producing and consuming events asynchronously, enabling real-time responsiveness.
Q11. Explain the importance of scalability in cloud computing. (6M)

Scalability is a cornerstone of cloud computing, offering the ability to dynamically manage resources based on demand.

  • Elasticity for Variable Workloads: Clouds can dynamically acquire and release computing resources. This supports variable workloads and accommodates large peak-to-average ratios without service degradation.
  • Cost-Effectiveness: Scalability allows a "pay-as-you-go" model. Organizations do not need to over-provision or invest heavily in hardware for peak times, significantly reducing capital expenditure.
  • Performance Maintenance: As demand spikes, automated scaling ensures that applications maintain optimal performance by distributing load across newly allocated servers.
  • Business Agility: Rapid scaling enables new businesses and expanding organizations to grow without being hindered by infrastructure limitations.
Q12. Illustrate with a neat diagram the architecture of cloud computing. (6M)

Cloud computing architecture is divided into two main parts: Front End and Back End, connected via the Internet.

  • Front End: Contains the client infrastructure and user interfaces (browsers, apps) that the end-user interacts with.
  • Back End: The robust cloud infrastructure managed by the provider. It houses the runtime cloud, storage, databases, and physical servers. It also encompasses the management component (resource allocation, traffic control) and security mechanisms ensuring data integrity.
Q13. Analyze major challenges faced in cloud computing. (6M)

Cloud computing faces significant challenges inherited from distributed computing and its utility nature:

  • Security and Trust: Unauthorized access, data theft, vulnerabilities of virtualization, malicious insiders, and account hijacking are paramount concerns.
  • Resource Management: Managing millions of distributed servers requires complex load balancing and handling rapid changes in load with often incomplete global state information.
  • Interoperability and Standardization: Lack of universal standards leads to vendor lock-in and hinders building an "Intercloud" (federation of clouds).
  • Availability of Service: Risk of massive system failures. Service-Level Agreements (SLAs) offer some protection but not against all damages.
  • Performance Unpredictability: Resource sharing can lead to fluctuating performance, especially for communication-intensive applications.
  • Software Licensing: Traditional hardware-based licenses struggle in distributed, elastic environments.
  • Economic/Legal Implications: Cross-border data storage complicates legal compliance regarding privacy and data ownership.
Q14. Examine how vulnerabilities lead to data breaches in cloud. (6M)

Cloud vulnerabilities, amplified by scale and shared environments, often pave the way for data breaches:

  • Malicious Attacks: High-profile clouds are prime targets for DoS attacks and traditional threats like SQL injection and cross-site scripting, which have a massive blast radius.
  • Shared Technology (Multitenancy): Virtualization flaws in the hypervisor (VMM) can allow a compromised guest VM to break isolation and access data of other tenants on the same physical server.
  • Account Hijacking: Stolen user credentials grant attackers unauthorized access to sensitive data stored in the cloud.
  • Malicious Insiders: Opaque hiring policies at Cloud Service Providers mean rogue employees could exploit their privileged access to leak or steal data.
  • Insecure APIs: Weak Application Programming Interfaces can fail to authenticate properly, leaving data exposed to unauthorized manipulation or extraction.
  • Virtualization Specifics: Saved VM states, shared public images (AMIs) with leftover credentials, and management OS (Dom0) vulnerabilities provide backdoors for attackers.

In cloud computing, Open Source Software Platforms serve as the control infrastructure for building and managing private clouds. Examples include Eucalyptus, OpenNebula, Nimbus, and OpenStack, which allow organizations to configure their own cloud environments securely.

The Intercloud is a conceptual "cloud of clouds" – a federation of independent clouds cooperating to provide a superior, seamless user experience, much like how the Internet is a network of interconnected networks.

Q18. What is energy consumption in cloud systems? (2M)

Energy consumption in cloud systems refers to the massive power drawn by large-scale data centers for processors, storage, and networking. It has major economic and ecological impacts, driving the need for "Energy-Proportional Systems" where power usage scales directly with workload.

Q19. Define user experience in cloud services. (2M)

User experience in cloud services encapsulates users' concerns and perceptions regarding security, data ownership, forced updates, system reliability, and the fuzzy boundaries of liability between the user and the cloud provider.

Q20. State the challenges of software licensing in cloud computing. (2M)

Traditional software licensing is based on named users or physical hardware (site licenses), which is incompatible with the dynamic, distributed, and elastic nature of cloud computing. Adapting these models to pay-per-use or cloud-based metrics remains a significant challenge.

Q21. Describe the types of cloud storage and their uses. (6M)

Cloud storage comes in various formats to meet different application needs:

  • Block Storage: Highly scalable, persistent storage that acts like a raw hard drive. It is ideal for applications demanding ultra-fast read/write performance (e.g., databases). Example: AWS EBS.
  • Object Storage (Off-instance): Data is stored as objects in buckets, highly accessible via APIs. Best for storing unstructured data, media files, and backups. Example: AWS S3.
  • Instance-Lifetime Storage: Temporary storage physically attached to the host computer of a virtual machine. Data is lost when the instance is terminated.

Cloud Storage Diversity (RACS): To prevent vendor lock-in and data loss, Redundant Array of Cloud Storage (RACS) strips data across multiple cloud providers (like RAID-5 for disks), enhancing reliability and availability.

Q22. Explain open-source software platforms for cloud computing. (6M)

Open-source platforms are used to build private or hybrid clouds, providing control infrastructure comparable to commercial public clouds. Key platforms include:

  • Eucalyptus: An open-source counterpart to AWS EC2. It features a strong separation between user and admin spaces, making it ideal for large corporate private clouds. Components include Node controller, Cluster controller, and Storage controller (Walrus).
  • OpenNebula: A centralized system defaulting to NFS. Highly customizable, it is suited for small-to-medium groups of knowledgeable users for testing or edge deployments.
  • Nimbus: Based on Globus software, it is primarily designed for scientific applications requiring broad customization.
  • OpenStack: A massively scalable cloud operating system initiated by NASA and Rackspace. It controls huge pools of compute, storage, and networking resources throughout a data center via a dashboard.
Q23. Write about software licensing challenges in cloud computing. (6M)

Software licensing is a persistent hurdle in cloud adoption due to the fundamental differences between traditional IT and cloud environments.

  • Inadequacy of Traditional Models: Existing licenses were designed for centrally managed environments, tied to specific hardware MAC addresses, CPUs, or named users. Cloud computing's elasticity (spinning instances up and down) breaks this model.
  • The SaaS Solution: SaaS alleviates this by shifting to a subscription or pay-per-use model, but IaaS and PaaS users still struggle with bringing their own licenses (BYOL) to the cloud.
  • Pressure for Change: Users demand non-hardware-based solutions to avoid paying for peak licenses continuously.
  • Research Solutions: Projects like SmartLM research complex infrastructures involving Service Level Agreements (SLAs), negotiation protocols, and dynamic authentication to handle cloud-native licensing.
Q24. Explain responsibility sharing in cloud infrastructure. (6M)

The Shared Responsibility Model dictates the security and management boundaries between the Cloud Service Provider (CSP) and the user, varying by deployment model:

  • Software-as-a-Service (SaaS): The CSP manages almost everything (hardware, OS, application, security). The user is only responsible for their data, interface configuration, and access credentials.
  • Platform-as-a-Service (PaaS): The CSP manages the underlying infrastructure (servers, network, OS). The user is responsible for the applications they deploy and the data within them.
  • Infrastructure-as-a-Service (IaaS): The CSP provides basic resources and physical security (Compute, Storage, Network). The user carries heavy responsibility: managing the OS (patching), firewall configurations, applications, and data security.
Q25. How does User experience affect cloud adoption? (6M)

User experience and perception heavily dictate the pace and nature of cloud adoption.

Concerns Hindering Adoption:

  • Fear of security threats, data theft, and loss of control over sensitive data.
  • Fuzzy boundaries of liability and lack of trust in third-party providers.
  • Legal issues regarding data location and compliance.
  • As a result, highly sensitive workloads (healthcare, finance) are often kept off public clouds.

Factors Driving Adoption:

  • Cost Savings: "Pay-as-you-go" pricing, saving on hardware, software licenses, and maintenance.
  • Agility: Rapid deployment, scalability, and ability to use the latest technology immediately.
  • Focus: Allows organizations to offload IT support and focus on core business competencies.
Q26. Describe architectural styles in cloud computing. (6M)

Cloud applications typically follow specific architectural communication styles to ensure scalability and efficiency:

  • Request/Response with Stateless Servers: The most common style. Servers treat each client request independently without retaining connection state. This makes systems highly robust and scalable, as load balancers can route requests to any available server seamlessly.
  • Communication of Structured Information: Overcoming differences in architecture and languages by serializing data over the network.
  • Remote Procedure Call (RPC): Uses stubs to convert parameters (marshalling/serialization) for client-server interaction.
  • Object Request Broker (ORB): Middleware that transforms internal data structures to byte sequences for networked objects.
  • Simple Object Access Protocol (SOAP): XML-based message format stacked over HTTP/TCP, forming the basis for many enterprise Web Services.
  • Web Services Description Language (WSDL): An XML grammar used to describe communication endpoints, abstracting operations and port bindings.
Q27. Write short notes on multi-cloud strategy. (6M)

A multi-cloud strategy involves an organization using services from more than one public cloud provider (e.g., AWS, Azure, Google Cloud) rather than relying on a single vendor.

  • Avoiding Vendor Lock-in: Ensures the company isn't trapped by one provider's pricing or policies, allowing them to migrate workloads if necessary.
  • Best-of-Breed Services: Organizations can choose the best specific service from different providers (e.g., Google for AI/ML, AWS for robust compute).
  • Reliability and Disaster Recovery: Distributing resources across multiple clouds creates a highly resilient environment; an outage in one cloud won't take down the entire business.
  • Cloud Storage Diversity (RACS): Multi-cloud can be used to replicate data or use RAID-like stripping (Redundant Array of Cloud Storage) across providers to prevent catastrophic data loss.
  • Challenges: Increases management complexity, integration difficulties, and requires diverse skill sets among IT staff.
Q28. Explain the concept of cloud paradigms. (6M)

Cloud computing establishes new paradigms for application development and deployment, characterized by elastic resources on demand.

Existing Paradigms & Applications:

  • Processing Pipelines: Used for data-intensive indexing, document conversion, and video transcoding.
  • Batch Processing Systems: Enterprise tasks with deadlines, utilizing MapReduce for large datasets.
  • Web Applications: Standard stateless architectures leveraging cloud elasticity.

New Application Opportunities:

  • Data Proximity: Storing data close to the compute nodes reduces bandwidth costs and drastically increases processing efficiency.
  • Business Analytics & Science: Cloud provides the massive parallel compute power required for modern analytics, ML, and scientific research.
  • Mobile Interactive Apps: Processing heavy sensor data or mashups in the cloud rather than on resource-constrained mobile devices.

Unit 3

Q29. What is a Virtual Machine (VM)? (2M)

A Virtual Machine (VM) is an isolated software environment that simulates a complete physical computer. It has its own virtual CPU, memory, and storage, appearing to run on bare hardware while actually sharing the physical resources of the host machine.

Q30. What are virtual machine monitors? (2M)

A Virtual Machine Monitor (VMM), or hypervisor, is the software layer that sits between the hardware and the virtual machines. It securely partitions system resources, manages concurrent execution of VMs, and enforces isolation among them.

Q31. Differentiate between full and para virtualization. (2M)

In Full Virtualization, the VM runs on an exact copy of the actual hardware, so the guest OS requires no modifications. In Paravirtualization, the VM runs on a modified hardware abstraction, requiring the guest OS to be explicitly modified to communicate efficiently with the hypervisor.

Q32. What is hardware support for virtualization? (2M)

Hardware support refers to extensions built directly into processor architectures (like Intel VT-x or AMD-V) to assist the hypervisor. They introduce new processor modes (VMX root/nonroot) to efficiently manage CPU states and memory without excessive software overhead.

Q33. Define virtualization and explain its types. (6M)

Virtualization is a fundamental technique that abstracts underlying hardware resources, simulating interfaces to physical objects to isolate users and increase system elasticity.

Types based on mechanisms:

  • Multiplexing: Creating multiple virtual objects from one physical object (e.g., CPU multiplexing).
  • Aggregation: Combining multiple physical objects into one virtual object (e.g., RAID storage).
  • Emulation: Constructing a virtual object from a different physical type.

Types of Virtual Machines:

  • System VMs: Provide a complete system running an entire OS (e.g., Traditional/Bare-metal, Hosted, Hybrid VMs).
  • Process/Application VMs: Run under a normal OS providing a platform-independent host for a single app (e.g., Java Virtual Machine).
Q34. Compare full virtualization and para virtualization. (6M)

Full Virtualization:

  • Hardware Abstraction: Provides an exact replica of the underlying physical hardware to the VM.
  • Guest OS: Runs completely unmodified. It is unaware it is being virtualized.
  • Execution: Relies heavily on the VMM to trap and emulate privileged instructions, which can introduce performance overhead. Examples: VMware.

Paravirtualization:

  • Hardware Abstraction: Provides a slightly modified hardware interface that is easier to virtualize.
  • Guest OS: Must be explicitly modified (ported) to use special hypercalls to interact with the VMM.
  • Execution: Often yields higher performance because the guest OS proactively cooperates with the hypervisor, avoiding expensive trap-and-emulate cycles. Examples: Xen.
Q35. Describe hardware support for virtualization. (6M)

Traditional processor architectures with only User and Kernel modes struggle with virtualization because the VMM needs a higher privilege level than the guest OS Kernel. Modern hardware provides specific extensions to solve this:

  • x86 Architecture Extensions (Intel VT-x / AMD-V): Introduced new operation modes: VMX Root (for the hypervisor) and VMX Non-root (for the guest OS). It includes the Virtual Machine Control Structure (VMCS) to rapidly swap processor states during VM entry and exit, eliminating software emulation bottlenecks.
  • I/O MMU Virtualization (Intel VT-d): Hardware support that maps virtual memory addresses directly to physical I/O devices. This allows a VM direct access to network cards or GPUs (PCI pass-through), drastically improving I/O performance and security.
  • Network Virtualization (VT-c): Assists in offloading network virtualization tasks directly to the hardware.
Q36. Write about resource allocation in virtual environments. (6M)

Resource allocation in virtual environments is managed by the Virtual Machine Monitor (VMM), which securely partitions and distributes physical hardware among multiple VMs.

  • CPU Allocation: The VMM multiplexes the physical CPUs. It traps privileged instructions and manages scheduling, ensuring concurrent execution of multiple guest operating systems without interference.
  • Memory Management: The VMM allocates isolated blocks of physical memory to each VM. It maintains shadow page tables to handle dynamic address translation between the guest's virtual memory and actual physical memory via the MMU.
  • Performance Isolation: A critical goal of resource allocation is to guarantee Quality of Service (QoS). The VMM must prevent "noisy neighbors," ensuring one VM consuming heavy CPU or I/O does not degrade the performance of other VMs sharing the host.
  • Live Migration: Proper resource abstraction allows the VMM to capture a VM's state (CPU, memory) and seamlessly move it to another physical server to balance load or reduce power consumption.

Cloud Computing Question Bank Answers

Unit 1

Q1. Define Cloud Computing. (2M)

Cloud Computing means storing and accessing your data and applications over the internet, instead of using your computer's local hard drive. The processing and storage happen in distant data centers.

Q2. List the types of computing. (2M)
  • Distributed Computing
  • Parallel Computing
  • Cluster Computing
  • Grid Computing
  • Utility Computing
  • Edge Computing
  • Fog Computing
Q3. State any two needs for cloud computing. (2M)
  • Cost Savings: You don't have to buy expensive hardware. You only pay for what you use.
  • Scalability: You can easily increase or decrease computing resources based on your current needs.
Q4. What are the main components of Cloud Computing Architecture? (2M)

It is divided into two main parts: the Front End and the Back End. Components include:

  • Client infrastructure
  • Application
  • Service
  • Runtime cloud
  • Storage
  • Infrastructure
  • Management
  • Security
  • Internet
Q5. Differentiate between network-centric computing and network-centric content. (2M)

Network-centric computing: Using processing power from distant servers over the internet instead of your local PC.

Network-centric content: Storing files, photos, or videos (like on iCloud or Google Drive) over the internet so you can access them from any device.

Q6. Name the three primary cloud service models. (2M)
  • Infrastructure as a Service (IaaS)
  • Platform as a Service (PaaS)
  • Software as a Service (SaaS)
Q7. Define cloud computing and explain its essential characteristics (6M)

Definition: Cloud computing lets you store data and run applications over the internet instead of on your local hard drive. It shifts the heavy lifting from your computer to giant data centers.

Essential Characteristics:

  • Elasticity: The cloud acts like a rubber band. It can automatically add more servers when traffic is high and remove them when traffic is low.
  • Pay-as-you-go (Metered Usage): Just like your electricity bill, you only pay for the exact amount of cloud resources (like storage or processing) that you actually use.
  • Provider takes care of Maintenance: The cloud company (like Amazon or Google) does all the hard work of fixing hardware, updating software, and handling security.
  • Economy of Scale: Because cloud providers buy massive amounts of hardware, it becomes much cheaper. They pass these cost savings down to the users.
  • Access from Anywhere: Your data isn't locked to one device. You can access your files from your phone, laptop, or tablet, no matter where you are in the world.
Q8. Explain the layered architecture of cloud computing. (6M)

Cloud architecture is basically how everything in the cloud connects and works together. It has three main parts:

  • Front End (What you see): This is the user's side. It includes your mobile phone, laptop, web browser, and the apps you use to connect to the cloud.
  • Back End (What the provider manages): This is the "brain" of the cloud. It contains:
    • Storage: Where all the data is kept.
    • Servers & Infrastructure: The physical machines doing the processing.
    • Management & Security: Tools to keep hackers out and ensure the system runs smoothly.
  • Network (Internet): The bridge that connects the Front End to the Back End.

Network Centric Computing Layers:

  • Information Layer: Keeps data safe and ensures quality.
  • Network Layer: Handles smooth communication and prevents internet traffic jams.
  • Control Layer: Manages the actual physical servers and hardware.
Q9. Explain various computing service models (IaaS, PaaS, SaaS). (6M)

These models decide who does what—you or the cloud provider.

  • Infrastructure as a Service (IaaS):
    • What it is: Renting raw hardware (servers, storage) over the internet.
    • Who controls it: You control the operating system and apps. The provider only manages the physical machines.
    • Example: Amazon Web Services (AWS EC2).
  • Platform as a Service (PaaS):
    • What it is: A ready-made environment for developers to build and test apps without worrying about setting up servers.
    • Who controls it: You just write the code. The provider handles the servers, storage, and operating systems.
    • Example: Google AppEngine.
  • Software as a Service (SaaS):
    • What it is: A finished software application you use over the internet (usually in a browser).
    • Who controls it: The provider handles absolutely everything (maintenance, updates, servers). You just log in and use it.
    • Example: Gmail, Google Docs, Netflix.
Q10. Explain distributed systems architecture in detail. (6M)

A distributed system is a group of independent computers working together to look like one single, powerful computer. Key architectural styles include:

  • Client-Server: The classic model. A "Client" (like your browser) asks for a webpage, and a "Server" gives it to them.
  • Peer-to-Peer (P2P): No central boss. Every computer (peer) acts as both a client and a server, sharing files directly with each other (like BitTorrent).
  • Multi-tier (N-tier): Splitting an app into layers to make it easier to manage. Usually: a Presentation layer (UI), a Logic layer (rules), and a Data layer (database).
  • Microservices: Breaking a massive app into tiny, independent pieces that talk to each other. If one piece fails, the whole app doesn't crash (Netflix uses this).
  • Service-Oriented Architecture (SOA): Creating reusable services that can plug into each other easily, often used by big corporations.
  • Event-Driven Architecture (EDA): Systems that react instantly to "events" (like a sensor detecting heat), often used in smart home devices.
Q11. Explain the importance of scalability in cloud computing. (6M)

Scalability means the cloud can grow or shrink its resources automatically. It is super important for these reasons:

  • Handling Traffic Spikes: If a website suddenly gets a million visitors (like during a Black Friday sale), scalability ensures the site doesn't crash by instantly adding more servers.
  • Saving Money: You don't have to buy 100 servers just in case you need them someday. You can start with 2 servers, and only pay for more when you actually need them.
  • Saves Time for Developers: Programmers don't have to worry about the system breaking under heavy load. The cloud handles the extra weight automatically.
  • Fast Business Growth: A new startup can grow from 10 users to 10,000 users overnight without needing to buy, install, or set up new physical hardware.
Q12. Illustrate with a neat diagram the architecture of cloud computing. (6M)

Cloud architecture is split into two main sides, connected by the internet.

  • Front End: This is what the user touches. It includes your laptop, mobile phone, web browser, and the apps you use.
  • Back End: This is the hidden engine of the cloud managed by the provider. It includes:
    • Storage: Giant hard drives storing all the data.
    • Infrastructure/Servers: The physical computers doing the math.
    • Management: Software that makes sure everything runs smoothly without crashing.
    • Security: Firewalls and encryption to keep hackers out.
Q13. Analyze major challenges faced in cloud computing. (6M)

Even though the cloud is great, it has some major challenges:

  • Security and Trust: The biggest fear. Users are handing their private data to someone else. What if the provider gets hacked or an employee steals data?
  • Vendor Lock-in: If you build your whole business on AWS, it is very hard and expensive to suddenly switch to Google Cloud. You are "locked in" to one vendor.
  • Service Outages: If the cloud provider's internet goes down or their servers crash, your business completely stops working until they fix it.
  • Unpredictable Performance: Because you are sharing servers with other companies, if another company gets a massive traffic spike, your website might run slower.
  • Software Licensing: Old software was sold on CDs for one computer. It's hard to figure out how to charge for software that runs on 1,000 virtual cloud computers at once.
  • Legal Issues: If your data is stored on a server in another country, which country's privacy laws apply? It gets very confusing.
Q14. Examine how vulnerabilities lead to data breaches in cloud. (6M)

Because the cloud is massive and shared, tiny security holes can lead to huge data breaches:

  • Shared Server Risks: In the cloud, your data lives on the same physical server as a stranger's data. If the software keeping you separated (the hypervisor) has a bug, a hacker can jump the fence and steal your data.
  • Stolen Passwords: Account hijacking is common. If a hacker steals an employee's cloud password, they can log in and download everything.
  • Rogue Employees (Insiders): A dishonest employee working at the cloud company has the keys to the kingdom and could secretly steal sensitive customer data.
  • Weak APIs: Apps use APIs to talk to the cloud. If an API is poorly written, hackers can trick it into handing over private data.
  • Public Image Mistakes: Sometimes people accidentally leave passwords or secret keys inside public Virtual Machine images. Hackers scan for these and use them to break in.

Unit 2

Q15. What is Open Source Software Platform? (2M)

These are free software tools (like OpenStack or Eucalyptus) that companies use to build and manage their own private clouds on their own hardware.

Q16. Define Inter-cloud. (2M)

The Inter-cloud is the idea of a "cloud of clouds." It means connecting different cloud providers together so they can share resources seamlessly, just like how the internet connects different networks.

Q17. List any two cloud storage types. (2M)
  • Block Storage: Fast, raw storage for databases (like an external hard drive).
  • Object Storage: Storage for files, photos, and backups (like Google Drive or S3 buckets).
Q18. What is energy consumption in cloud systems? (2M)

It refers to the massive amount of electricity required to run and cool giant data centers. The goal is to create "energy-proportional" systems where power is only used when actual work is being done.

Q19. Define user experience in cloud services. (2M)

User experience is about how users feel using the cloud. It includes their fears about security, worries about losing data, and their reliance on a fast internet connection.

Q20. State the challenges of software licensing in cloud computing. (2M)

Old software licenses were meant for a single physical computer. In the cloud, virtual computers are created and destroyed constantly, making traditional software licensing almost impossible to track fairly.

Q21. Describe the types of cloud storage and their uses. (6M)

Cloud storage comes in different flavors depending on what you need:

  • Block Storage: Acts like a traditional hard drive attached to a computer. It is very fast. Best for: Databases and high-speed applications.
  • Object Storage: Stores data as "objects" inside buckets. It is cheap and can scale infinitely. Best for: Storing photos, videos, documents, and backups.
  • Instance Storage: Temporary storage attached to a virtual machine. Best for: Temporary files or caches, because the data is erased when the machine turns off.

RACS (Redundant Array of Cloud Storage): To avoid losing data if a cloud provider crashes, RACS splits your data into pieces and stores it across multiple different cloud companies. If one fails, you can rebuild your data from the others.

Q22. Explain open-source software platforms for cloud computing. (6M)

These are free software tools companies use to build their own private clouds. The top four are:

  • OpenStack: The most famous one. Built by NASA and Rackspace. It is heavily used by big enterprises to manage huge amounts of servers, storage, and networking through a web dashboard.
  • Eucalyptus: This tool was built to work exactly like Amazon Web Services (AWS). It’s great for companies that want an AWS-style cloud running inside their own private building.
  • OpenNebula: A very simple and lightweight tool. It's easy to set up and is often used by research labs or small businesses to manage a small group of servers.
  • Nimbus: Designed specifically for the scientific community. It focuses on heavy data processing and complex scientific research needs.
Q23. Write about software licensing challenges in cloud computing. (6M)

Paying for software in the cloud is complicated for several reasons:

  • The Old Rulebook Doesn't Work: Traditional software was sold per physical computer (using MAC addresses). But in the cloud, virtual computers are created and deleted every hour. You can't easily track licenses this way.
  • SaaS is Easy: Software as a Service (like Netflix or Gmail) solves this by just charging a monthly subscription per user. No license keys are needed.
  • Users Hate Overpaying: If a company only uses heavy cloud servers for 2 hours a day, they don't want to pay for a 24/7 software license. They want to "Bring Your Own License" (BYOL) and pay per minute.
  • Future Solutions: Researchers are creating new systems (like SmartLM) that use digital tickets to track software usage second-by-second across the cloud, ensuring fair billing.
Q24. Explain responsibility sharing in cloud infrastructure. (6M)

The "Shared Responsibility Model" decides who is blamed if something goes wrong—you, or the cloud provider.

  • SaaS (Software as a Service): The provider does almost everything. They secure the servers, the network, and the app. Your job: Just keep your password safe and manage your account settings.
  • PaaS (Platform as a Service): The provider manages the underlying servers and operating systems. Your job: You are responsible for the custom code you write and the data your app collects.
  • IaaS (Infrastructure as a Service): The provider only secures the physical building and the physical servers. Your job: You do the heavy lifting. You must install antivirus, set up firewalls, update the operating system, and secure your data. If you get hacked, it is usually your fault.
Q25. How does User experience affect cloud adoption? (6M)

How users feel about the cloud controls whether companies decide to use it.

Why people are scared to use it (Hindrances):

  • Fear of Hackers: Users are terrified of giving their private customer data to a third party.
  • Losing Control: They don't like not knowing exactly which country their data is physically stored in.
  • Vendor Lock-in: They fear being trapped by one provider and not being able to leave if prices go up.

Why people love it (Drivers):

  • It Saves Money: You don't have to buy expensive servers or pay for maintenance. You only pay for what you use.
  • It is Fast: You can launch a new server in 2 minutes, instead of waiting 3 weeks to buy and install physical hardware.
  • Less Headache: The cloud provider handles the boring IT maintenance, letting the company focus on its actual business.
Q26. Describe architectural styles in cloud computing. (6M)

Cloud apps are built in specific ways so they don't break when millions of people use them.

  • Stateless Servers: This is the golden rule of the cloud. A "stateless" server forgets who you are after every click. If the server crashes, another server can instantly take over your next click without missing a beat. This makes scaling up incredibly easy.
  • RPC (Remote Procedure Call): A trick that lets a program run a piece of code on a distant cloud server as if the server was sitting right on the user's desk.
  • SOAP (Simple Object Access Protocol): A strict, XML-based language that lets different programs securely talk to each other over the internet.
  • WSDL (Web Services Description Language): A digital rulebook that tells programs exactly how to talk to a SOAP service so they don't get confused.
Q27. Write short notes on multi-cloud strategy. (6M)

A multi-cloud strategy is when a company uses more than one cloud provider (like using AWS, Google Cloud, and Microsoft Azure all at the same time).

Why it’s a great idea:

  • No Vendor Lock-in: You aren't trapped by one company. If AWS raises prices, you can move your work to Azure.
  • Extreme Safety: If a massive storm takes out Google Cloud entirely, your business stays online because AWS is still running.
  • Using the Best Tools: You can use Google for its amazing AI tools, and use AWS for its cheap storage. You get the best of both worlds.

The bad parts:

  • It's Complicated: Your IT team has to learn how to use three different systems instead of just one.
  • Hidden Costs: Moving data between different cloud providers can be very expensive due to transfer fees.
Q28. Explain the concept of cloud paradigms. (6M)

Cloud paradigms are the new, innovative ways we can build apps now that we have unlimited computing power.

How we use it now:

  • Processing Pipelines: Perfect for heavy, boring tasks like converting 10,000 Word documents into PDFs or compressing video files.
  • Batch Processing: Analyzing massive amounts of data overnight using frameworks like MapReduce.
  • Web Apps: Running scalable websites like Netflix or Facebook.

Cool new things we can do:

  • Data Proximity: Moving the "brain" to the data. Instead of downloading a massive dataset to analyze it, we send the analysis software directly into the cloud to process the data where it lives.
  • Mobile Offloading: Your phone battery is weak, so apps send complex math (like voice recognition) to the cloud to be processed instantly, returning only the answer to your phone.

Unit 3

Q29. What is a Virtual Machine (VM)? (2M)

A Virtual Machine is a software program that acts exactly like a physical computer. It has its own fake CPU, memory, and hard drive, allowing you to run a full operating system inside a window on your real computer.

Q30. What are virtual machine monitors? (2M)

A Virtual Machine Monitor (VMM), or Hypervisor, is the software boss. It sits between the physical hardware and the virtual machines, splitting up the CPU and memory fairly and keeping the VMs safely separated.

Q31. Differentiate between full and para virtualization. (2M)

Full Virtualization: The virtual machine thinks it's a real computer; the guest OS is completely unmodified.
Paravirtualization: The guest OS is specially modified to know it's a virtual machine, allowing it to run much faster.

Q32. What is hardware support for virtualization? (2M)

It means computer chips (like Intel and AMD processors) have special features built inside them to help the hypervisor run virtual machines faster, removing the need for slow software tricks.

Q33. Define virtualization and explain its types. (6M)

Definition: Virtualization is the magic trick of cloud computing. It uses software to create fake (virtual) versions of physical things like computers, storage, or networks.

Ways to do Virtualization:

  • Multiplexing: Taking one physical thing and splitting it into many virtual things (e.g., slicing 1 physical CPU to run 4 virtual machines).
  • Aggregation: Taking many physical things and gluing them together into one giant virtual thing (e.g., combining 10 hard drives to look like one massive drive).
  • Emulation: Pretending to be something else entirely (e.g., software pretending to be an old Nintendo console).

Types of Virtual Machines:

  • System VMs: These pretend to be a whole computer and run a full operating system like Windows or Linux.
  • Process VMs: These are temporary and just run a single application (like Java) and disappear when the app closes.
Q34. Compare full virtualization and para virtualization. (6M)

These are two different ways to run a virtual machine.

Full Virtualization:

  • The Illusion: The hypervisor creates a 100% perfect fake copy of the physical hardware.
  • Guest OS: The operating system inside (like Windows) is totally unmodified. It has no idea it is inside a virtual machine.
  • Speed: Slower. Because the guest OS doesn't know it's virtual, the hypervisor has to secretly translate and double-check every important command, which causes delays.

Paravirtualization:

  • The Illusion: The hardware is slightly modified for efficiency.
  • Guest OS: The operating system is modified. It knows it is a virtual machine.
  • Speed: Faster. Because it knows it's virtual, it doesn't try to touch the hardware directly. Instead, it politely asks the hypervisor to do things using special "hypercalls," skipping the slow translation steps.
Q35. Describe hardware support for virtualization. (6M)

In the past, running virtual machines using only software was very slow. Now, companies like Intel and AMD build special features directly into the physical chips to speed things up.

  • CPU Extensions (Intel VT-x / AMD-V): Older processors only had two modes (User and Kernel). Virtualization required a third mode for the hypervisor, causing massive headaches. New chips add special "VMX" modes so the hypervisor and the guest OS can both run smoothly without fighting for control.
  • Fast Switching (VMCS): The hardware now includes a special memory structure that lets the computer instantly switch back and forth between different virtual machines without lagging.
  • Direct Hardware Access (Intel VT-d): Normally, the hypervisor handles all network and graphics data, slowing things down. VT-d lets a virtual machine bypass the hypervisor and talk directly to the physical network card or graphics card, resulting in blistering fast speeds.
Q36. Write about resource allocation in virtual environments. (6M)

Resource allocation is how the Hypervisor (VMM) fairly chops up the physical computer and hands the pieces to the virtual machines.

  • CPU Sharing: The hypervisor acts as a traffic cop. It rapidly switches the physical CPU between different virtual machines so fast that every VM thinks it has its own dedicated processor.
  • Memory Management: The hypervisor gives each VM an isolated chunk of RAM. It uses "shadow page tables" to secretly map the fake memory inside the VM to the real physical memory chips on the motherboard.
  • Stopping Noisy Neighbors: The hypervisor ensures strict limits (Quality of Service). If one VM gets a virus and tries to use 100% of the CPU, the hypervisor restricts it so the other VMs on the server don't slow down.
  • Security Walls: The hypervisor builds impenetrable walls. A hacker inside VM #1 cannot see the memory, files, or network traffic of VM #2.
